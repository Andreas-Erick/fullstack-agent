# ENG-10 (part): the phone client split into modules: doc wording

## CLAUDE.md, companion.js paragraph (where it says "Also serves the phone client `renderer/remote/` (plain files, no build, own CSP; only the paths listed in `STATIC`)")
Add after it:
- The phone client is ES modules in `renderer/remote/`, split along its old banners: `app.js` wires them and boots (the Android globals `nexusShare`, the `nexusTalk` fallback, the background and app-lock switches, the tablet layout, keyboard shortcuts, `initScreens`, the service worker, the pairing/move link at load); `state.js` the shared state (`state`, `chat` from turnstate, `store`, `inputEl`, `$`, the storage keys) and the Android bridge (`android`, `bridge()`; it asks `hello()` for the key when it loads); `ui.js` (`el`, `icon`, `markdown`, `toast`, `ago`, the script-error trap, `AuthError`/`NetError`, `setConvTitle`, `submitForm`, `plainLoadError`); `net.js` (`fetchWithin`, `tunnelDown`, `answerError`, `api`); `pairing.js` (pairing, `offerApp`, `unpair` and the two-tap Disconnect, `show`, moving to the secure address, `renderLinkInfo`); `stream.js` (the SSE stream, `dispatch`, `checkStream`, `retryNow`, `onDataChanged`, `onInfoChanged`, `setConn`); `offline.js` (`renderOffline`, `renderBanner`, `insecure`); `chatview.js` (`onChat`, the turn views, `renderTurn`, `send`, the composer, `prefill`, the suggestions); `conversations.js` (`loadConversation`, `keepUnsent`, `followRunning`, `refreshConvs`, the drawer); `approvals.js` (`KIND`, the cards); `voiceout.js` (`say`, `setSpeak`); `talk.js` (push-to-talk, `MAX_REC_MS`, `nexusTalk`, `nexusMicBlocked`); `face.js` (`refreshFace`, `agentState`, `mountFace`, the custom face frame, `applyScene`, full screen, the fallback orb); `schedule.js`; `nav.js` (`showView`, `syncBack`, `nexusBack`, `wide`/`applyWide`); `hud.js` (`setFx`, `decode`, the splash); `boot.js` (`start`, `applyInfo`, `noteClient`). The modules import each other in cycles; that is safe because at load they only declare things, bind listeners and call function declarations (hoisted), never read another module's constants. `state.js` and `ui.js` import none of the others, so they load first (the error trap and `hello()` before anything else). A new module of the client goes into `companion.js` `STATIC` and `sw.js` `MODULES` (bump `CACHE`); `test/sync.test.js` checks every module is served, loaded and cached, and that `state.js` makes the first bridge call. Tests that read the client's source use `test/helpers.js` `phoneClientSource()` / `phoneClientFiles()`.

## Notes for the reviewer
- Pure moves: function bodies are unchanged. Exports were added for what other modules use; `$` is exported from `state.js`.
- Load order differs from the single file (ES modules load depth-first): listeners on the same target may register in a different order (document `keydown`/`pointerdown`, `#micBtn` `pointerdown`). Each handler is independent of the others, so the order doesn't matter.
- `scripts/check.js` and `main/codemap.js` (`isModule`) now treat every `renderer/remote/*.js` but `sw.js` as an ES module, so `screens.js` and `sync.js` are syntax-checked and their imports verified too (they were not before).
- `main/archcore.js`: new phone components `remote-core`, `remote-link`, `remote-chat`; the curated client→server link starts at `net.js`.
