# Siren Assistant — notes for the agent modifying itself

(Formerly Nexus Agent. Internal identifiers keep the old name on purpose: the `NEXUS_*` environment variables, `window.nexus` in the renderer, `window.NexusAndroid`, the `nexus-agent` ping id the phone checks, `startedByNexus`, the Android package `com.nexusagent.android` and the appId `com.nexus.agent` (so installs upgrade in place). User-visible text says Siren / Siren Assistant.)

This file is read by the assistant (and Claude Code) before changing this codebase. Keep it accurate when the architecture changes.

## Shape of the app
Electron app, plain JavaScript, **no build step**. Node ≥ 22. Run `npm start` (dev mode with DevTools: `npm run dev` / `dev.bat`); syntax-check with `npm run check`.

- `main/` — Electron main process (CommonJS, Node APIs).
  - `main.js` window, `app://` protocol (serves only whitelisted folders, see `SERVED`), every IPC handler (`handle('ns:method', fn)`; the three raw handlers `win:zoom`, `win:fullscreen`, `win:overlay` (they need `e.sender`) check `fromApp(e)` first, like `handle()`). `applySaved(s, patch)` is what a settings save sets in motion beyond the file (the voice shortcut, logging, `companion.apply`, helper apps, the router): `settings:set` calls it after a save that went through, `settings:reset` with every section (remote access stops at once when the reset turns it off) and still returns `{ settings, kept }`.
  - `llm.js` providers + agent tool loop: `openai` (FreeLLMAPI, SSE), `anthropic` (Anthropic SDK, required lazily: only the anthropic provider loads it, `test/modules.test.js`), `claude-code` (delegates to `claudecode.js`), `auto` (multi-provider: `router.js`).
  - `router.js` multi-provider mode: the user's ranked list (`routing.order`), smart per-task preference, cooldowns after rate limits / credit caps. Gemini, DeepSeek, Groq, Perplexity run through the OpenAI path via `router.concrete(settings, id)`. A turn falls back to the next provider only before any tool ran (no action runs twice); streamed text is retracted. `runTurn` returns `provider`, stored on the assistant message.

Any router provider id can be `llm.provider` on its own (`llm.narrow`); Settings, the brain pill (`SINGLE` in `app.js`), the HUD and Health handle those ids too.

Hand-over (`llm.handOver`, off by default, user-only, `test/handover.test.js`; `handOverTarget` considers only a brain on the OpenAI path, `provider === 'openai'`, since `isLocal` alone also called a Claude brain local when an old `llm.baseUrl` still pointed at localhost): `llm.runSingle` sends a local brain's message to the Claude brain (claude-code, else anthropic, when ready) straight away for `localcore.handOverHint` (a picture, code work, a connector by name, a long text), or when the local model calls `hand_over`; a routine (`runTurn` `routine`) that names a connected service (`localcore.neededService`) goes to Claude even with the setting off, and a routine's text never counts as engineering (it gets the larger round budget only) (offered only then; never after a tool that isn't `localcore.isReadTool` ran in the turn: `ctx.wrote`); the local text is retracted and a notice says so. A first reply that gives up without a tool (`localcore.gaveUpUnlooked`) is retracted and the model is asked once to look (`LOOK_FIRST`; kept out of the stored turn). Likewise a reply that claims an action no tool did in the turn (`localcore.claimsAction`: first-person "I've added…", "X done."), asked once to do it or say it isn't done (`CLAIM_CHECK`, unstored). A message naming one of the user's personas loads the persona tools (`hintGroups` `personas`). `localcore.requestExtras` adds `keep_alive: '30m'` and, unless the pace is deep, `reasoning_effort: 'none'` to local requests (`runOpenAI` retries without them on a 400). ## Conventions
- Match the surrounding style: 2-space indent, single quotes, semicolons, small focused functions, short comments only where they add context.
- New setting: add a default in `store.js` `DEFAULTS`, a control in `renderer/js/settings.js` (`text()`, `toggle()`, `select()` helpers (number fields are text inputs read by `settingsave.parseNumber`: empty or invalid saves nothing and the last good value comes back on blur, "1,000" accepted; `folder()` and the cliPath field go through `settingsave.cleanPath`) bind to `section.key` paths and auto-save).
- New tool: add it to its group file in `main/tools/` (a new group: a new file, listed in `TOOLS` in `main/tools.js`) with a clear description; give it a label in `TOOL_LABELS` in `renderer/js/chat.js`.
- New view: rail button + `<section>` in `index.html`, a module with `init*()`/`refresh()`, wire it in `app.js`.
- Renderer-only changes need a window reload; `main/`, `preload.js` or `package.json` changes need an app restart.
- New npm dependencies can't be installed by the agent; ask the user to run `npm install <pkg>`.

## When something is broken

## Logging (`main/logger.js`)
- `log.info|warn|error(event, data)`: short event name, details as an object. Pass the Error object itself (`{ error: err }` or as data), not `err.message`: the logger keeps message, code, cause and stack.
- Work that belongs to a turn runs inside `log.withContext({ turn, conv })` (set in `main.js` `chat:send`; tools get it through `ctx.logTags`, Claude Code output through `Session.inTurn`). New async entry points should do the same.
- Never log secrets or whole documents/prompts; the logger masks known key formats, but don't rely on it. `log.debug` only writes when debug logging is on.
- Renderer code logs through `logEvent(level, event, data)` (lines appear as `ui: …`).
- Repeats: a line repeated within 10 s becomes `(previous line repeated N more times)`. It is written right after that line, at its level and at the time of the last repeat. `tail()` (like `flush()`) writes pending repeats before it reads. `errorinsight.analyze` adds a marker's count to the group of the row above it. `errorinsight.normalize` folds UUIDs into one id, and a line without a JSON detail (a window's `ui: …` text) is grouped by its normalized event.
- Stack frames are shortened one at a time (`shortFrame` / `shortFile`). A file inside the app is its path from the app's folder (`path.resolve(__dirname, '..')`, any case, `file://` URLs decoded) or the part after `app://bundle/`, e.g. `main/llm.js:499:23`. Any other file keeps only its name, and an eval frame's inner positions are treated the same way. Never the folders above the app: they hold the user's name.
- One failure, one line: for the app's own tools (`mcp__nexus` / `mcp__nexus_more`), `claudecode.js` skips results that are tools.js's JSON, because tools.js logged them with arguments and stack. CLI refusals (`<tool_use_error>`), bridge errors (`Error: …`), connectors and Claude Code's own tools are logged as WARN `tool failed`. A call the user declined (`User did not approve…` / `Not approved by the user…`) is INFO `tool declined`, with the words of a spoken decline replaced by "(N characters said)" (`approvals.declineForLog`). A routine turn whose brain isn't ready (`routinecore.brainNotReady`) or that failed offline (`routinecore.offline`) logs WARN `turn not ready` instead of ERROR `turn failed`; a stopped turn logs INFO `turn interrupted`. The window's `reply failed` (chat.js) is INFO: main.js already logs the turn's `turn failed` ERROR with its stack, so a failed reply is one problem report.
- A message run again logs INFO `turn again` (kind again|regenerate|edit, fresh, acted, uncertain, from window|device); an attempt record that couldn't be written is WARN `could not record the attempt` / `could not record the failed attempt`. Attachments log only kinds, extensions, sizes and counts (`attachment prepared`, `attachment refused`, `attachment evicted`, `attachments expired`, `attachments swept`; WARN `text extraction failed` with `why`, `text extraction skipped`), never names or text.
- INFO `turn`, `reply` and the window's `heard` carry lengths (`chars`), ids and timings, not words; `turn text`, `reply text` and `heard text` are DEBUG lines (written only with Detailed logging on; `log:write` passes 'debug' through). Other INFO lines still carry some of the user's content: `tool` keeps the first 300 characters of a tool's input (tools.js, claudecode.js), `approval` / `ui: approval requested` the approval's title, `journaled` the conversation's topic. The `approval` line keeps `reason` only for the app's own fixed reasons (Deny, Esc, 'The user said no.', the time limit, Stop, no window, a device's no); a spoken answer is `reasonChars` (`approvals.reasonForLog`; the words only at DEBUG `approval reason`). The model still gets the words.
- A string detail with line breaks is written on one line (` | ` between the parts). An ERROR line carries `trail`: the names (event, level, seconds before; never details) of up to ten lines just before it, the same turn's, else the last minute's, masked like the rest (`logger.js` `trailFor`); `errorinsight.parseLine` reads it and a problem report shows it as "Just before (event names only)", a name that isn't plain words as "(other)". `NEXUS_LOG_DEBUG=1` turns detailed logging on from the first line. Every page with the preload calls `util.installErrorTrap()` (main window, viewer, agent window): an uncaught error is logged as `{ error: { message, stack } }` and its console copy is not logged again (`captureConsole` skips `Uncaught`); `captureConsole` also logs a failed preload, a page that didn't load and (other windows) a crash. A window's line whose data names its `turn` (the last 6 characters of the requestId) is written under that turn's tag (`log:write`). IPC errors from the file system reach the window as words naming only the file (`main/plainerror.js` `plainIpcError`). `test/observability.test.js`. The crash handlers (`uncaughtException`, `unhandledRejection`) log the Error itself (`{ error: err }`): one line, short app paths, code locations for `analyze_errors`.
- A value the user chose that Electron refuses is logged as data, never as an Error: the voice shortcut logs `voice shortcut not registered` with `accel` and `reason` ('in use by another app', or the refusal's message). An Error's stack would point into the app's code and count against a self-change in `verifyAfterLoad`. Damaged data (an unreadable file) is a WARN for the same reason.

## Safety rails (do not remove)
- `approvals.js` gating, the external-content notice in `tools/common.js` (applied in `tools.js`), the `SETTABLE` allowlist (the agent can't change safety/permissions/code access/secrets), and the standing rules in `prompt.js`.
- The outside-content rules: the taint marked at a result's arrival, the warning on every dialog of a tainted turn, `TAINT_ASKS` / `TAINT_EACH_TIME` / `taintAsks`, a connector's deletes and invitations after outside content (`connectors.taintedAsk`), `askOutbound` with its redirect checks (web_fetch, browser_open), and no 'Always allow' from a tainted turn. Also approve()'s deny of the vault's own folders, vaultgit's hooks and file monitor turned off, and Stop closing a turn's approvals (`newTurn({ signal })`).
- `selfchange.js` records every change in git; `scripts/recover.js` undoes the last change if the app no longer starts.
- Crash safety nets (see TROUBLESHOOTING.md → Crashes and recovery): the per-file write queue and settings backup/recovery in `store.js` (a damaged section repaired, a copy kept before a reset, `asConversation`), the boot boundary in `renderer/js/app.js` (`start`), the test runs' time limits (`scripts/test.js`, `selfchange.run`), the per-child handlers and start-failure retry in `claudecode.js`, the speech-to-text timeout/reload and playback time limits in `renderer/js/voice.js`, window-crash reload in `main.js`.
- Path checks in `files.js`/`codebase.js`/`documents.js`, the private-network block in `websearch.js`, `navguard.js` (a link in content never navigates an app window), `cliValue`/`spawnCli` in `claudecode.js` (nothing a model or a page wrote reaches a command line), the rules in `test/electronboundary.test.js`, and the IPC surface in `preload.js` protect the user — keep them.
- `companion.js` / `tunnel.js`: the Host/Origin checks, the Cloudflare Access verification, the tunnel token kept out of the command line and logs, the "Remote" pill's one-click off, token check on every route, the approval-id allowlist (`openApprovals`: secret and recording prompts share the pending map and must never be answerable remotely), and the narrow route list. Never add settings, secrets, tools or arbitrary files to it: the phone's data screens go only through `companiondata.js` (trimmed copies; notes only inside the vault; no writes at all) behind `remote.shareData` (user-only); the village's code and art are served from fixed lists (`STATIC`, `WORLD_ART`).

- Screen sharing starts only from the user's click (never from a tool), screenshots are tainted as external content and never stored; the PDF renderer keeps JavaScript off and the network blocked. Attached files and pictures taint the turn the same way (the UNTRUSTED_NOTICE in `attachcore.compose`, `taint` per attachment); `chat:attach` takes bytes, never a path, and `attachments.js` checks them again (extension and first bytes, the worker thread's heap, time and memory limits, the zip-bomb check, `SAFE_EXTS` for saved copies).
