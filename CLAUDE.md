# Siren Assistant — notes for the agent modifying itself

(Formerly Nexus Agent. Internal identifiers keep the old name on purpose: the `NEXUS_*` environment variables, `window.nexus` in the renderer, `window.NexusAndroid`, the `nexus-agent` ping id the phone checks, `startedByNexus`, the Android package `com.nexusagent.android` and the appId `com.nexus.agent` (so installs upgrade in place). User-visible text says Siren / Siren Assistant.)

This file is read by the assistant (and Claude Code) before changing this codebase. Keep it accurate when the architecture changes.

## Shape of the app
Electron app, plain JavaScript, **no build step**. Node ≥ 22. Run `npm start` (dev mode with DevTools: `npm run dev` / `dev.bat`); syntax-check with `npm run check`.

- `main/` — Electron main process (CommonJS, Node APIs).
  - `main.js` window, `app://` protocol (serves only whitelisted folders, see `SERVED`), every IPC handler (`handle('ns:method', fn)`).
  - `llm.js` providers + agent tool loop: `openai` (FreeLLMAPI, SSE), `anthropic` (Anthropic SDK), `claude-code` (delegates to `claudecode.js`), `auto` (multi-provider: `router.js`).
  - `router.js` multi-provider mode: the user's ranked list (`routing.order`), smart per-task preference, cooldowns after rate limits / credit caps. Gemini, DeepSeek, Groq, Perplexity run through the OpenAI path via `router.concrete(settings, id)`. A turn falls back to the next provider only before any tool ran (no action runs twice); streamed text is retracted. `runTurn` returns `provider`, stored on the assistant message.
  - `screenshare.js` screen sharing (desktopCapturer thumbnails): started/stopped only by the user; `capture()` gives a JPEG data URL. Images reach the model as `images` on `runTurn` and as `__image` in tool results (`look_at_screen`); `stripImages` keeps them out of stored conversations.
  - `persona.js` + `personacore.js` personas: the live `agent.*`, `appearance.*`, `ui.face`, `voice.voice`/`localVoice` settings are always the active persona; `store.setSettings` copies them into its entry in `personas.list` on every save (`personacore.sync`), and a switch (`persona:switch`, tool `persona_switch`) swaps another one in. Code that reads the name, prompt, theme or face needs no persona logic. The agent changes its own look with `theme_update` (validated by `persona.themeChange`) but can't create personas or edit master prompts.
  - Learning: `learning.js` (vault I/O) over the pure `learningcore.js` (the understanding tracker, `Learning/<Topic>.md`: understood / shaky / misconceptions / open questions / log) and `srs.js` (vocabulary decks with SM-2, `Languages/<Language>.md`, schedule in `<!-- srs … -->` comments). Tools `learning_*`, `vocab_*` (group `learning`, needs the vault) and `language_practice` (sets `learning.practiceLanguage`: speech recognition and the voice switch language, see `renderer/js/practice.js`). The teaching method is `teachingBlock()` in `prompt.js`; the tracker summary goes into the stable prompt, practice mode into the per-turn context. `personatemplates.js` ready-made personas (STEM tutor, polyglot coach).
  - Habits: `habits.js` over the pure `habitcore.js` (`Habits.md` in the vault: habits with a weekly target in `<!-- habit … -->` comments, a dated log; streaks and weekly stats). Tools `habit_*` (group `habits`, needs the vault), the Habits view (`renderer/js/habits.js`), a per-turn line in `prompt.turnContext`. Coaching guidance is `coachingBlock()` in `prompt.js`.
  - Skill tree: `skilltree.js` gathers the evidence (learning topics, deck maturity, habit consistency) for the pure `skilltreecore.js` (`Skill Tree.md`: one line per skill with a JSON `<!-- skill … -->` comment: area, needs, from; no cycles; progress and states computed, never stored; the constellation layout). Tools `skilltree_*`, the Tree view (`renderer/js/skilltree.js`, SVG).
  - Memory stream (after Generative Agents): `stream.js` (vault I/O: the user's stream is `Stream/YYYY-MM.md`, residents' streams are single notes; last-recalled times in `<userData>/stream-access.json`; background reflection, one at a time per stream) over the pure `streamcore.js` (one record per line with a `<!-- rec {...} -->` comment, `retrieve` = recency + importance + TF-IDF relevance, min-max scaled; `pending`/`reflectionPrompt`/`parseReflections` with evidence ids). Tools `stream_*` (group `stream`, setting `memory.stream`); `prompt.turnContext(…, { query })` adds "Recalled from your memory stream" for the user's message (`llm.runOn` passes it).
  - Inner World: `innerworld.js` (daily check, one narrator call per day while awake: `innerWorld.enabled`, user-only; state in `<userData>/innerworld.json`; `Inner World/Chronicle.md` and `Inner World/Residents/<name>.md` in the vault; pushes `world:event` to the window only) over the pure `worldcore.js` (PLACES and their levels from real evidence, residents = personas + townsfolk, the narrator prompt and `parseDay` validation). Rehearsals: `rehearsal.js` over the pure `rehearsalcore.js` (one model call per character turn, private goals only in that character's prompt, a capped number of turns, a debrief; saved in `Inner World/Rehearsals/`). Tools `world_*` (group `world`) and `rehearsal_run` (group `rehearsal`, needs only the vault). Live work: `startTurn`'s emit in `main.js` calls `innerworld.noteTool` on every `tool_start` (both brains); `worldcore.workFor` maps the tool to a place, counts go to `<userData>/innerworld-activity.json` (they grow the Workshop and the Lookout and reach the narrator via `workLines`) and a `world:event` `work` sends the active persona there. View: `renderer/js/innerworld.js` (data, camera: drag, wheel, double-click to step inside; residents walk the roads with `map.route`; panels; live work) over `renderer/js/world/`: `map.js` (pure, `test/worldmap.test.js`: the floating island on a 40×40 tile grid, heights, river and waterfall, roads as a minimum spanning tree, sites, trees, routes), `art.js` (isometric drawing kit: boxes, half-timbered/stone/plank walls, shingled roofs, windows, doors, towers, domes, terrain tiles and cliffs, trees, props, villagers), `places.js` (each place by level, with emitters for moving parts and lights), `interiors.js` (cutaway rooms that show the user's data, with labels), `scene.js` (the island cached as a bitmap of the visible region at the current zoom, rebuilt when the view or the data changes; per frame the sky, constellations, clouds, water, emitters, residents, night light, weather, labels). `view().details` carries what the village paints (topics, decks, habits, skills, memory counts, work counts). Rendered art: `world/sprites.js` loads `renderer/assets/world/` (WebP sprites + `manifest.json`: size, anchor, named points such as chimney tops; variants summer/winter/autumn/glow), made by `tools/world-art/` (Blender script + blueprints over Kenney's CC0 kits; see its README; `test/worldsprites.test.js`). Homes fill `map.lots` as the village grows (`sceneData().homes`), mills sit at `map.mills` (wheel/blade frames drawn per frame by the `frames` emitter), crops follow the season on `map.fields`; accent roofs (blueprint colour ACCENT) have a `roofmask` variant that `sprites.tintRoofs` colours with the theme; a second design per place (`<place>-<level>b`) is picked per install (`sceneData().designs`). `places.js` uses a place's sprite when `innerWorld.art` is 'rendered' (default) and draws only the data overlays on top; trees, props and road lamps likewise; without sprites everything falls back to code. Seasons: `world/season.js` (pure; the date, the hemisphere from the time zone, or `innerWorld.season`) feeds `palette(season)`; art.js draws snow, bare trees, ice, autumn leaves and blossom from `P.season`. Camera controls (glide, pinch, keyboard, follow) and the minimap are in `innerworld.js`. Ideas not built yet: `docs/ROADMAP-inner-world.md`. **Colour exception:** the village is an illustration, so `art.js` has its own natural palette (`STORY`), lightly tinted by the theme; theme accents colour banners, magic lights and some roofs. The rest of the app stays on theme tokens.
  - Routines: `routines.js` (stored in `<userData>/routines.json`, checked every minute, one run at a time) over the pure `routinecore.js` (schedules, `check()` = run / skip a too-late missed run / wait, the run prompt). A run is `startTurn` in `main.js` with `display`, `routine` and `onFinish`, in the routine's own conversation; `routine:event` goes to the window and a Windows `Notification` when unfocused. Tools `routine_*`; saving or deleting asks the user.
  - Agent Skills folders: `skills.js` reads `<userData>/skills/<slug>/SKILL.md` + companion files (`readFile`, tool `skill_file`); `skillimport.js` imports them from a public GitHub repo (3 API calls + raw files at a commit; text only, size limits, `.source.json` + the repo's LICENSE kept; tool `skill_import`, Skills view → Import).
  - `diagrams.js` + tool `diagram_save`: self-contained HTML/SVG into `<vault>/Diagrams/`, sanitized (no scripts, handlers, frames, external links); `docview.js` shows HTML in a sandboxed `srcdoc` iframe (no scripts, works under the viewer's `frame-src 'none'`).
  - `extensions.js`: MCP servers Nexus adds to Claude Code sessions (`claudecode.sessionSpec` → `spec.extensions`, merged into the session's mcp.json; tool search on; permission levels as for connectors, even with connectors off): REA (`npx rea-agents@<pinned> mcp`) and God's Eye View (the user's checkout: `server/mcp/stdio.js`, and its dev server on :4173, started/stopped by Nexus). The globe shows in the agent window (`agentwindow.js`); `claudecode.js` starts its server when a session has the extension. Settings `extensions.*` are user-only (never SETTABLE; `test/extensions.test.js`).
  - `archmap.js` + the pure `archcore.js` the Architecture view's map (rail "Arch", `renderer/js/archmap.js`, a canvas with semantic zoom: containers → components → files → symbols): `archmap.scan` reads every source file (codemap's JS files, renderer pages/styles, Android Java) into facts (imports, `api.*` calls, `api.on` events, `webContents.send`, outside systems by the `EXTERNALS` patterns); `archcore.build` classifies them (`CONTAINERS`, `COMPONENTS`; an unclaimed file becomes an `auto` component), adds the curated `LINKS`, lays it out and lists `PRINCIPLES` for the Learn panel. Cached in `<userData>/archmap.json` with a file fingerprint (stale → "Code changed: rebuild"); `arch:build` rescans and diffs (new parts marked). **A new main/renderer module should be added to a component in `archcore.js` `COMPONENTS`** (with an about, and a lesson when it embodies a design idea); `test/archmap.test.js` fails on rules that name files which no longer exist.
  - `agentwindow.js` the agent window: a `BrowserWindow` whose own page is the toolbar and the frame around the site (`renderer/agentwindow.html` + `js/agentwindow.js`, main preload, `agentWindow:*` IPC, theme and `ui.fx` re-read on focus; `BAR`/`INSET` in `agentwindow.js` must match `.aw-bar`/`.aw-frame` in `styles.css`) with the site in a `WebContentsView` inside the frame (no preload, session `persist:agentwindow`, permissions and downloads off, local/private addresses blocked on navigation and in `webRequest`, except the globe on :4173). The pure part (URL policy, address bar, in-page read/locate scripts) is `agentwindowcore.js`. Tools `browser_open/read/look/act/close` (group `browser`, setting `agentWindow.enabled`, user-only); `browser_act` click/type/select go through approval kind `browser` and refuse password/payment fields. `docwindows.js` treats it as the window "agent window" (move, full screen).
  - `claudeusage.js` the Claude plan meter: the CLI's `rate_limit_event` → windows with utilization and reset times, cached in `<userData>/claude-usage.json`, pushed as `claude:usage` to the title-bar pill (`renderer/js/usage.js`, setting `ui.showClaudeUsage`). Stopping a Claude turn sends the CLI's interrupt request (`Session.interrupt`) instead of killing the process; `claude session restarts` in the log names what changed.
  - `sysmon.js` the title-bar system monitor (CPU, RAM, disk, GPU via one long-lived `nvidia-smi --loop-ms` or a PowerShell GPU-engine counter loop): samples only while the window calls `system:watch(true)` (visible and `ui.showSystemStats` on), pushes `system:stats` to the window only. The details panel also asks `system:bluetooth` (connected devices via a fixed, encoded PowerShell query; only while the panel is open) and `system:network`; `netspeed.js` is the speed test (Cloudflare endpoints), run only by `system:speedtest` from the user's click. Never give it to tools, the prompt, the log or `companion.js` (`test/sysmon.test.js`). Renderer: `renderer/js/sysmon.js`.
  - Performance profiles (`perf.mode`: auto | balanced | full, user-only): the window checks the hardware (`renderer/js/perf.js` → `hardware:scan`, classified by the pure `renderer/js/perfcore.js`, stored as `perf.detected`/`perf.hw`). `profile()` exists twice and must agree (`renderer/js/perfcore.js`, `main/perfcore.js`; `test/perf.test.js`). Balanced: `speechPlan()` (model, processor-only, multilingual for other languages), speech and offline voice unloaded after idle (`voice.js`), `effectsLevel()` caps HUD to subtle, `body.perf-lite` (no backdrop blur, opaque panels) and `body.fx-rest` (animations paused when unfocused/asleep) set in `hud.js`, faces via `env.lite()` (30 fps, 1× DPR, no shadowBlur), Claude sessions capped (`sessionsToClose`) with a shorter idle time, helper apps stopped on quit. Measured: in-app Whisper needs >1 GB while loaded even with base.en (the ML runtime), plus GPU-process memory on WebGPU. `main/resources.js` (+ `system:usage`/`system:free`) feeds the system monitor's "Nexus" section; like sysmon, user-only.
  - `capabilities.js` + tool `capabilities_for`: which skills, connectors/plugins and extensions fit a task (pure `match`): `use` vs `suggest`.
  - Folder access: `documents.userFolders(settings)` = workspace + `documents.allowedRoots` (user-added only, never SETTABLE); nothing else by default. Claude Code gets them as `--add-dir`; Read/Glob/Grep are not pre-allowed and `approve()` checks paths against `spec.readRoots`.
  - `guide.js` the feature guide behind "how can I use you?" (tool `app_guide`, skill `/tour`): one entry per area with what it does, things to say, where it is, and a live status. **Add or update an entry whenever a feature changes.** `notelock.js` serializes read-modify-write of one vault note (habits, learning topics, decks, skill tree) and, inside such a change, `obsidian.readOptional`/`writeNote` compare the note's mtime so an outside edit in between makes the change run again (`NOTE_CHANGED`). `lru.js` caps the note cache.
  - `skills.js` Agent Skills (`<userData>/skills/*.md`, frontmatter + steps; the bundled ones in `main/skills/` are copied in once, `.bundled.json` remembers which); `/slug args` in `chat:send` is expanded to the steps (`display` keeps what the user typed). `pdf.js` Markdown/HTML → PDF in a hidden, script-less, offline window. `hardware.js` hardware scan + recommendations.
  - `companion.js` remote access (docs/ROADMAP-mobile.md): HTTP + SSE server, with `/api/data/*` for the phone's screens (`companiondata.js`: today, habits + check-off, learn, tree, memories, stream, notes, note, world, skills, routines; only while `remote.shareData` is on) and the phone client's `screens.js` (tabs Chat/Today/Habits/Learn/More; the Inner World drawn with `renderer/js/world/*`, served with its art). Tailscale: `tunnel.detectTailscale` (name, HTTPS on, Serve forwarding) and `setupTailscaleServe` (`remote:setupTailscale`, the user's click: `tailscale serve --bg --yes <port>`, or the link to enable HTTPS). The server: off by default (`remote.*`, desktop-only, not in `SETTABLE`), 127.0.0.1 or LAN. Pairing code → device token (only its hash in `remote-devices.json`). Host/Origin checks, token on every call. Scope: chat (`startTurn` in `main.js`, never a screenshot, never the setup conversation: its events go through `toWindow`), conversations and the schedule (`/api/schedule`) read-only, approvals it was sent (`send()` publishes `chat:event` / `approval:*` to devices). Devices get trimmed copies (`chatForDevice`, `messageForDevice`: tool names only, never inputs or results); a device unused for 90 days is unpaired. Also serves the phone client `renderer/remote/` (plain files, no build, own CSP; only the paths listed in `STATIC`), `/api/info`, `/api/face` + `/f/<key>/…` (the active custom face by a ten-minute per-device link, `facelinks.js`: served under its own CSP with `sandbox allow-scripts` and `connect-src 'none'`, framed sandboxed by the client; links revoked on unpair or stop), `/api/face/frames` (the face recorded as JPEG loops per state for the watch, `facecapture.js` + `renderer/facecapture.html` in a hidden offscreen window, cached by face/theme/name, ETag), `/api/speak` and `/api/transcribe` (phone push-to-talk; the window transcribes via `remote:transcribe`, see `renderer/js/remote.js`, which also runs the title-bar "Remote" pill).
    Moving to the secure address: a device on the LAN gets a one-time secret (`/api/move`) that, redeemed through the tunnel only (`/api/pair` `{ move }`), rotates its token (same device). `/api/info` carries `secureUrl`.
    Devices can be view only (`setReadOnly`, `remote:setReadOnly`, Settings → Remote access): `VIEW_ONLY_BLOCKED` POSTs get 403, approvals are not streamed to them, `/api/info` carries `readOnly` (the client hides the composer). Setting `journal.handoffOnClose`.

## Conventions
- Match the surrounding style: 2-space indent, single quotes, semicolons, small focused functions, short comments only where they add context.
- New setting: add a default in `store.js` `DEFAULTS`, a control in `renderer/js/settings.js` (`text()`, `toggle()`, `select()` helpers bind to `section.key` paths and auto-save).
- New tool: add it to `TOOLS` in `main/tools.js` with a clear description; give it a label in `TOOL_LABELS` in `renderer/js/chat.js`.
- New view: rail button + `<section>` in `index.html`, a module with `init*()`/`refresh()`, wire it in `app.js`.
- Renderer-only changes need a window reload; `main/`, `preload.js` or `package.json` changes need an app restart.
- New npm dependencies can't be installed by the agent; ask the user to run `npm install <pkg>`.

## Engineering method, checks and tests
- `docs/ENGINEERING.md` is how to change this app well: the loop (understand → design → plan → implement → verify → review → commit → learn), design principles, cross-file checklists, security review, tests, debugging, definition of done. Read it before anything beyond a small fix.
- `npm run check` = syntax of every file, then `scripts/verify.js`: integrity across files (IPC handler ↔ preload channel ↔ renderer `api.*` call, relative imports/requires and the names they import, settings keys bound in Settings or in `SETTABLE` exist in DEFAULTS, unique tool names; tool labels as a warning). It reads the code statically through `main/codemap.js` (also behind `code_map` / `code_outline`).
- `npm test` = `test/*.test.js` with Node's built-in runner (no dependencies, offline, a few seconds). `test/modules.test.js` loads every `main/` module with an Electron stand-in and checks every tool's schema, so load-time mistakes fail the tests, not the app's start. Load main modules with stand-ins via `test/helpers.js` (`stub`, `load`, `fileStore`). New logic gets tests; a bug fix gets a regression test.
- `selfchange.commit` (and so every self-change) records a change only if check and tests pass, then marks it pending; after the next restart/reload `verifyAfterLoad` checks the log (`main/errorinsight.js` groups problems) and reports problems to the user, the agent's context (`prompt.turnContext`), Health and Evolution.
- Engineering mode (`main/engineering.js`): coding, self-change and debugging turns get `llm.engineeringToolRounds` (40) tool rounds and at least "high" effort on the Claude API; a turn that starts a self-change is upgraded mid-way.

## When something is broken
Read `TROUBLESHOOTING.md` (→ Reading the log), run `analyze_errors` (distinct problems with code locations) and `diagnose`, read the log (`read_app_log` with the failing line's `turn` id) — then fix the cause, with a regression test.

## Logging (`main/logger.js`)
- `log.info|warn|error(event, data)`: short event name, details as an object. Pass the Error object itself (`{ error: err }` or as data), not `err.message`: the logger keeps message, code, cause and stack.
- Work that belongs to a turn runs inside `log.withContext({ turn, conv })` (set in `main.js` `chat:send`; tools get it through `ctx.logTags`, Claude Code output through `Session.inTurn`). New async entry points should do the same.
- Never log secrets or whole documents/prompts; the logger masks known key formats, but don't rely on it. `log.debug` only writes when debug logging is on.
- Renderer code logs through `logEvent(level, event, data)` (lines appear as `ui: …`).

## Safety rails (do not remove)
- `approvals.js` gating, the external-content notice in `tools.js`, the `SETTABLE` allowlist (the agent can't change safety/permissions/code access/secrets), and the standing rules in `prompt.js`.
- `selfchange.js` records every change in git; `scripts/recover.js` undoes the last change if the app no longer starts.
- Crash safety nets (see TROUBLESHOOTING.md → Crashes and recovery): the per-file write queue and settings backup/recovery in `store.js`, the per-child handlers and start-failure retry in `claudecode.js`, the speech-to-text timeout/reload and playback time limits in `renderer/js/voice.js`, window-crash reload in `main.js`.
- Path checks in `files.js`/`codebase.js`/`documents.js`, the private-network block in `websearch.js`, and the IPC surface in `preload.js` protect the user — keep them.
- `companion.js` / `tunnel.js`: the Host/Origin checks, the Cloudflare Access verification, the tunnel token kept out of the command line and logs, the "Remote" pill's one-click off, token check on every route, the approval-id allowlist (`openApprovals`: secret and recording prompts share the pending map and must never be answerable remotely), and the narrow route list. Never add settings, secrets, tools or arbitrary files to it: the phone's data screens go only through `companiondata.js` (trimmed copies; notes only inside the vault; the one write is checking a habit off) behind `remote.shareData` (user-only); the village's code and art are served from fixed lists (`STATIC`, `WORLD_ART`).
- `helperapps.js` launches programs: their paths (`helperApps.*`) are settings only the user changes, never in `SETTABLE` (`test/helperapps.test.js` checks this), and only the two known apps can be started.
- Screen sharing starts only from the user's click (never from a tool), screenshots are tainted as external content and never stored; the PDF renderer keeps JavaScript off and the network blocked. See `PRIVACY.md` and keep it accurate when data flows change.
